# Flowra v2 최종 UI/UX — Codex 실제 적용 지침

## 작업 방식

현재 Flowra React+TypeScript 프로젝트의 구현을 우선 분석하고, v2 HTML을 **디자인 레퍼런스**로 활용하세요. HTML 전체를 iframe/웹뷰로 끼우거나 샘플 데이터를 서비스에 투입하지 마세요. 기존 컴포넌트, 토큰, API와 DTO를 재사용하고 미커밋 변경을 보존하세요. 디자인 구현은 한 번에 전체를 덮어쓰지 않고 단계별로 진행합니다.

### 단계별 적용 순서

1. **기존 1·2차 보존:** `ProjectDetail`, `ProjectWorkManager`, `ProjectWorkFormDialog`, `ProjectLocationPicker`, 380px 도킹, 모달 입력 보호 및 반응형 확인. UI 차이만 보완.
2. **3차 프로젝트 참여자·담당자:** 기존 회사 구성원 목록을 읽고 프로젝트 멤버십/Assignment API를 구분. 회사→프로젝트 추가·초대는 서버 계약이 지원하는 방식으로만 연결. Work Item 담당자 표시와 도킹 패널 배정 UI 연동. Phase 책임자 편집은 실제 API 확인 후 구현.
3. **4차 간트:** `/api/v1/company-projects/:id/gantt` 현재 계약과 기존 children API 확인. 왼쪽 WBS와 타임라인 동일 정렬·스크롤; 날짜 미설정은 막대 생성하지 않음. 일/주/월 축을 실제 날짜 계산으로 구현. existing Dependency 응답이 있을 때만 선을 표시. 간트 클릭 시 기존 공통 업무 상세 패널 열기. 드래그로 서버 날짜 수정은 이번 단계에서 제외.
4. **5차 관리자:** 회사 관리자의 별도 API/권한 확인. 전체 현황·프로젝트 목록·담당자별 업무량을 데이터 지원 범위에서 구현. 프로젝트 상태와 위험도는 분리. 직원별 시간/휴가/반차/충돌은 확인된 서버 API가 없으면 TODO 및 추가 요청으로 남김.
5. **실서버 통합 검증:** 타입 검사, 테스트, 기존 Mock E2E, 실제 서버, 권한, 320/390/768/1024/1440px, 낮은 화면 높이, 스크롤바, 모달 포커스, 도킹/오버레이 등 검증 후 커밋은 사용자 지시에 따라 수행.

## 참조 레이아웃 및 디자인 토큰

- 바탕: `#F7F8FB`; 카드: `#FFF`; 테두리: `#E5E9F1`; 강조: `#7535F3` — 실서비스에서는 현재 Flowra 변수 우선.
- 좌측 내비게이션: 기존 AppShell 사용, 재작성 금지.
- 프로젝트 헤더: 약 80~100px, 탭: 개요/업무 목록/간트/구성원.
- 업무 목록: 업무명/상태/우선순위/담당자/기간/진행률/메뉴, 행 높이 약 44~48px.
- WBS: 프로젝트·Phase·Work Item 깊이 정책과 `wbs_code`를 별도 관리; 표시 번호는 백엔드 값과 혼동하지 않기.
- 상세 패널: 도킹 380px, 좁은 영역 오버레이·모바일 전체 화면, 동일 업무 ID·공통 컴포넌트.
- 간트: 기본 WBS 트리 340px, 조절 175~490px, 행 46px, 날짜 헤더 58px, 오른쪽 가로 스크롤, 양쪽 세로 스크롤 동기화.
- 생성·수정: 기본 입력→고급 설정, 입력값 보호, 위치 후보와 적용 분리, 계획 기간은 기본 미설정.

## 기술적 계약

- 새 API·DTO·HTTP 메서드를 상상해서 만들지 않습니다. 미지원 기능은 TODO 및 백엔드 필요 항목으로 구분.
- 상태 자동 변경 금지(마감 경과는 경고만).
- 진행률은 서버 계약을 따름; `null`/미설정/수동 `0%` 보존.
- 업무의 부모 ID와 연결 Phase ID를 별도로 유지.
- 초대 수락 대기 등 실제 상태는 API가 지원하는 경우에만 사용.
- 관리자 집계는 현재 접근 권한이 있는 서버 데이터만 대상으로 계산.
- 데모 코드의 `Date.now()`/로컬 `tasks` 조작을 실제 CRUD 구현으로 전용하지 마세요.
- HTML 디자인에는 로컬 가상 사용자·업무·날짜가 포함됩니다. 실서비스 계정 데이터처럼 표현하지 마세요.

## UI 승인 체크

- [ ] 프로젝트 목록에서 검색, 상태 전환, 행 클릭이 자연스럽다.
- [ ] 프로젝트 개요의 '완료업무 비율'을 서버 자동 진행률로 잘못 읽지 않는다.
- [ ] 업무 트리의 5단계 들여쓰기, 부모/Phase 분리, 필터·표시 옵션이 명확하다.
- [ ] 간트의 일/주/월 눈금과 막대가 실제 날짜에 맞는다.
- [ ] 미설정·편측 날짜 업무에 가짜 기간 막대가 없다.
- [ ] 의존성 선은 선택적으로 표시되며 업무 ID와 일치한다.
- [ ] 업무 목록과 간트가 같은 업무 상세 패널을 열고 도킹 상태를 유지한다.
- [ ] 회사 구성원·프로젝트 참여자·업무 담당자를 명확히 구분한다.
- [ ] 관리자 KPI, 프로젝트 목록, 업무량이 일반 프로젝트 화면과 분리되어 있다.
- [ ] 기존 Phase/Work Item 생성·수정 모달의 모든 필드를 유지하며 데이터 초기화가 없다.
- [ ] 날짜 미설정, 수동 상위 기간 적용, 경고 후 저장 허용 정책이 유지된다.
