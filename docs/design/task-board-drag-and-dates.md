# 할 일 드래그와 독립 할 일 날짜

순서와 이동은 [공식 일반 사용자 API의 Tasks 계약](../backend-specs/api_general.md#tasks)을 따른다.

- 개인 일정에 연결된 할 일은 행을 드래그하여 앞/뒤 순서를 바꾼다. 손잡이와 제목 영역에서 드래그 가능하다.
- 다른 개인 일정의 행 사이 드롭은 `PATCH /tasks/:task_id`의 `schedule_id`와 `sort_order`로 소속과 삽입 위치를 함께 저장한다. 카드·헤더·빈 영역 드롭은 대상 일정 끝에 넣으며 접힌 카드도 받는다.
- 같은 일정 내 순서 변경은 `GET /tasks?schedule_id=:schedule_id`로 필터 없는 전체 목록을 조회한 뒤 `PATCH /schedules/:schedule_id/tasks/reorder`에 새 순서의 전체 ID를 보낸다. 검색·날짜·완료 상태로 화면에서 숨겨진 항목도 포함한다.
- 순번은 0부터 시작하며 완료 상태와 관계없이 일정의 모든 할 일을 대상으로 한다. 화면의 완료/미완료 그룹을 유지하고 드롭으로 완료 상태를 바꾸지 않는다. 화면에 보이는 그룹 내 위치와 서버의 전체 일정 순번을 구분한다.
- 독립 할 일은 서버에서 `sort_order: null`이고 마감일 오름차순·생성일 내림차순으로 조회한다. 독립 목록 내부 수동 순서는 사용자별 브라우저 localStorage에만 저장한다. 다른 기기나 브라우저로 동기화하지 않는다. 독립 목록으로 이동할 때 `PATCH /tasks/:task_id`에 `schedule_id: null`을 보내며 `sort_order`는 보내지 않는다.
- 일정의 할 일을 드래그할 때 화면 하단에 독립 목록으로 빼는 드롭 영역을 표시한다. 유효한 대상에는 테두리 또는 행 사이 위치 표시가 나온다.
- 저장 성공 후 출발·도착 일정 전체 목록을 다시 조회하여 서버가 정리한 주변 할 일 순번까지 반영한다. 실패 또는 응답 유실 시에도 목록을 재조회하여 실제 저장 결과를 확인한다. `TASK_ORDER_MISMATCH` 충돌 뒤에는 최신 전체 목록을 확인하고 다시 조작한다.
- 저장 중에는 중복 이동을 막는다. 선택 모드·편집 중에는 드래그를 끈다. 회사/타인 소유 일정에는 연결하지 않는다.
- 모바일·키보드의 이동 메뉴에서 다른 개인 일정에 연결하거나 독립 할 일로 이동할 수 있다. 목록의 할 일 행에 포커스를 두고 키보드 위/아래 방향키로 순서를 바꿀 수 있으며 개인 일정은 서버, 독립 목록은 브라우저에 순서를 저장한다.
- 검색·날짜 필터와 보드의 달은 이동 후에도 유지한다. 이동·순서 저장 후 별도의 저장 성공 안내는 표시하지 않는다. 선택창을 닫은 뒤 화면에 보이는 해당 할 일의 이동 메뉴 또는 제목 버튼으로 포커스를 옮기고, 해당 할 일이 보이지 않으면 화면에 보이는 검색 입력으로 포커스를 옮긴다.
- 독립 할 일 빠른 추가에 마감 날짜·시간을 제공한다. 날짜 선택 시 시간은 09:00이며 변경 가능하다. 날짜를 선택하지 않아도 생성할 수 있다. 편집에서 날짜를 변경·제거한다.
- 이동은 날짜와 완료 상태를 바꾸지 않는다. 일정 날짜와 다른 마감일은 편집 화면에서 실제 날짜까지 보여준다. 날짜 생성·수정·제거는 기존 Tasks API의 `due_datetime`을 사용한다.
- 과거 브라우저 전용 순서를 서버로 자동 이관하지 않는다. 일정의 순서는 별도의 순서 스냅샷·사용자별 revision 조회 없이 Task 응답의 `sort_order`를 사용한다.

2026-10-02 정리 후 검증: 미사용 순서 서버·DB 패키지·마이그레이션을 제거한 상태에서 웹 빌드와 데스크톱·모바일 순서·이동 테스트를 확인했다. 브라우저 테스트 21개가 통과했고 모바일의 마우스 드래그 3개는 기존 검사 조건에 따라 건너뛰었다. 모바일은 이동 메뉴와 키보드 방향키로 검사했다. 모의 API 검증이며 운영 서버의 저장·권한·DB 동시 처리는 이 검사에 포함하지 않는다.
