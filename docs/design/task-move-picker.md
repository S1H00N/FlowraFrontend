# 할 일의 이동 일정 선택

할 일 더보기 메뉴는 `다른 일정으로 이동…`, 일정에 연결된 경우 `독립 할 일로 이동`을 제공한다. 일정 후보는 별도 선택창에서 고른 뒤 `이 일정으로 이동`으로 저장한다.

- PC에서는 작은 대화상자, 모바일에서는 같은 대화상자를 화면 하단의 선택창으로 표시한다. 검색·기간·저장 버튼은 고정하고 후보 목록만 스크롤한다.
- 상단에 이동할 할 일과 현재 위치를 표시한다. 후보의 제목, 연도를 포함한 날짜·시간, 카테고리 또는 일정 유형, 장소를 구분해 표시한다. 종일과 여러 날의 일정도 명시한다.
- 동일한 제목과 시각의 후보에는 설명 미리보기와 일정 번호를 추가한다. 반복 일정은 각 날짜의 개별 회차가 이동 대상이다. 저장은 일정 이름 대신 `schedule_id`를 사용한다.
- 검색은 선택한 달의 제목·설명에 적용한다. 기간은 보드의 달과 별도로 변경할 수 있다. 기간이나 검색이 바뀌면 선택을 초기화하고, 이전 달의 후보를 다음 달의 조회 결과로 표시하지 않는다.
- 현재 연결된 일정, 회사 일정, 다른 사용자에게 공유받은 일정은 후보에서 제외한다. 완료된 개인 일정은 이동 후보에서 제거하지 않는다.
- 후보 조회의 로딩·실패·빈 결과를 구분한다. 저장 중에는 입력과 중복 실행을 잠근다. 저장 실패 시 선택창과 선택을 유지하고 창 안에 오류를 표시하여 다시 시도할 수 있게 한다.
- 취소·Escape 후 원래 더보기 버튼으로 포커스를 복원한다. 이동 후에는 화면에 보이는 해당 할 일의 이동 메뉴 또는 제목 버튼으로 포커스를 옮긴다. 해당 할 일이 보이지 않으면 화면에 보이는 검색 입력으로 포커스를 옮긴다.
- 터치 환경에서는 처음 열 때 검색 키보드를 띄우지 않는다. 검색 중 키보드가 열리면 실제 화면의 남은 높이에 맞춰 목록을 줄이고 하단 저장 버튼을 키보드 위에 표시한다. 긴 현재 일정의 이름은 줄 수를 제한하여 컨트롤이 밀리지 않게 한다.
- 목적 일정의 정보는 이동 데이터에 보관한다. 이동 후 검색·날짜 필터와 보드의 달을 유지하며, 별도의 저장 성공 안내는 표시하지 않는다.
- 이동은 소속과 순서를 변경한다. 할 일의 마감일과 완료 상태는 보존한다. 기존 이동 API, 독립 할 일의 브라우저 순서 저장, 실패 복구를 사용한다.
- 메뉴에서 다른 일정으로 이동할 때는 대상 할 일을 미리 조회하지 않고 `schedule_id`만 수정하여 서버가 맨 뒤에 추가하게 한다. 저장 응답을 받으면 선택창을 닫고 목록을 백그라운드에서 갱신한다. 드래그로 특정 위치에 넣거나 같은 일정에서 순서를 바꿀 때는 전체 목록 조회를 유지하며, 실패 시 목록 갱신이 끝난 뒤 재시도를 허용한다.

검증 대상은 중복 이름과 시각, 검색 및 기간 변경, 현재 위치 제외, 반복·종일·여러 날 일정, 다른 달로의 이동과 기존 필터·달 유지, 저장 실패 후 재시도, 모바일 좁은 화면, 키보드와 포커스 복원이다.
