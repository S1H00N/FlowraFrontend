# 일정 안의 할 일: 디자인·동작 명세

제안일: 2026-09-15 · 상태: 설계 제안, 서비스 미반영

[클릭 가능한 HTML 시안](schedule-task-composer.html)

시안은 샘플 데이터만 사용하며 새로고침하면 초기화된다. 실제 앱의 사이드바와 달력은 유지하고, 일정 편집 패널과 할 일 가져오기 선택창만 적용 대상으로 삼는다. HTML의 좌측 설명과 상단 시나리오 전환은 검토용이며 제품 화면에 포함하지 않는다.

## 1. 결정할 기본 원칙

- 할 일 하나에 연결 일정은 최대 하나. 독립 할 일은 연결 일정이 없다.
- 새 일정과 기존 일정에 같은 할 일 편집 영역을 제공한다.
- 새로 작성 / 독립 할 일 연결 / 다른 일정에서 이동 / 다른 일정에서 복사를 지원한다.
- 편집 화면의 일정·할 일 변경은 하단 저장 버튼으로 함께 반영한다.
- 앞서 제안한 완료 즉시 반영은 **편집 화면에서는 적용하지 않는다.** 편집 화면의 완료 변경도 저장을 기다리게 해 취소의 의미를 일관되게 한다. 편집 화면 밖 기존 할 일 목록의 완료 체크는 즉시 반영한다.
- 저장 전 변경에는 `새로 작성`, `연결 예정`, `이동 예정`, `복사 예정`, `수정 예정`, `연결 해제 예정`을 글자로 표시한다. 색만으로 구분하지 않는다.

## 2. 화면 A — 일정 편집 패널

기존 일정 편집 패널 폭과 배치를 유지한다. 좁은 화면에서는 전체 화면으로 전환한다. 순서는 일정 기본 정보 → 할 일 → 고정 저장 영역이다. 목록이 길어지면 본문만 스크롤하며 할 일 영역 안에 별도 스크롤을 만들지 않는다.

### 구성

1. **영역 제목:** `할 일`과 저장 후 연결될 개수. 완료 비율은 기존 일정에 저장된 할 일이 있을 때만 `완료 1 / 3`으로 표시한다. 신규 작성 중에는 진행률 막대를 표시하지 않는다.
2. **빠른 입력:** `새 할 일 입력…` + 텍스트 `추가` 버튼. Enter로 한 개 추가한 뒤 입력창을 비우고 포커스를 유지한다. 한글 조합 중 Enter는 제출하지 않는다. 공백 제목은 추가하지 않는다.
3. **가져오기:** 보조 버튼 `기존 할 일 가져오기`. 새 입력 바로 아래에 둬 긴 목록에서도 접근 위치가 일정하게 유지되게 한다.
4. **할 일 목록:** 제목, 작업 종류, 우선순위·마감 요약, 필요할 때만 원래 일정 표시. 제목을 누르면 해당 항목의 상세 설정을 펼친다. 여러 항목을 동시에 펼치지 않는다.
5. **저장 안내:** `일정을 저장하면 할 일 변경도 함께 반영됩니다.`
6. **고정 하단:** `취소` / 새 일정은 `일정 만들기`, 기존 일정은 `변경사항 저장`. 위에 `새로 작성 2 · 연결 1 · 이동 1`처럼 저장할 작업 수를 요약한다.

### 항목 디자인

- 왼쪽: 저장된 항목은 완료 체크, 아직 저장되지 않은 항목은 비활성 원형 표시. 시안에서는 기존 일정의 저장된 항목만 완료 체크를 지원한다.
- 가운데: 제목 14px/600, 최대 2줄. 보조 정보 12px. 전체 제목은 상세 설정에서 확인한다.
- 오른쪽: 저장 대기 항목의 `×` 접근 가능한 이름은 `목록에서 제외`. 기존 항목은 `연결 해제` 메뉴 또는 텍스트 버튼.
- 이동: `영업 미팅 → 이 일정` + 주황 계열 `이동 예정` 표시.
- 복사: `영업 미팅에서 복사` + 보라 계열 `복사 예정` 표시.
- 연결 해제: 항목을 즉시 없애지 않고 `연결 해제 예정`과 `되돌리기` 표시. 저장 후 독립 할 일이 된다.
- 신규 항목 추가 후 짧은 배경 강조와 스크린리더 알림. 편집 중에는 입력 순서를 유지하며 자동 재정렬하지 않는다.

### 상세 설정

| 필드 | 새로 작성 | 연결·이동 | 복사 |
| --- | --- | --- | --- |
| 제목 | 인라인 수정 | 수정 시 원본 할 일에 저장 | 복사본만 수정 |
| 우선순위 | 일정의 우선순위, 없으면 보통 | 원래 값 유지 | 원래 값으로 시작 |
| 마감 | 일정 종료 시각, 종료가 없으면 시작 시각 | 원래 값 유지, 없으면 마감 없음 | 원래 값 유지, 없으면 마감 없음 |
| 마감 방식 | 일정 종료에 맞춤 / 직접 지정 / 마감 없음 | 동일 선택 가능 | 동일 선택 가능 |
| 상태 | 미완료 | 원래 상태 유지 | 미완료로 초기화 |

`일정 종료에 맞춤`은 **현재 편집 중에만** 일정 시간 변경을 따라간다. 저장 시 구체적인 마감 시각으로 저장한다. 이후 다른 화면에서 일정 시간을 바꿔도 자동 연동하는 기능은 이번 범위에 포함하지 않는다. 날짜가 확정되지 않았다면 `일정 시간 설정 후 적용`을 표시한다.

빠른 입력창에 작성 중인 제목이 남아 있을 때 저장하면, 유효한 제목을 마지막 신규 할 일로 포함한다. 빈 입력은 무시한다. 제목·마감 검증에 실패하면 해당 필드로 포커스를 이동하고 다른 변경도 저장하지 않는다.

## 3. 화면 B — 기존 할 일 가져오기

데스크톱은 최대 600px 모달, 작은 화면은 전체 화면 선택창. 제목·검색·탭·하단 버튼은 고정하고 결과 목록만 스크롤한다. 닫으면 호출 버튼으로 포커스를 복원한다.

### 기본 화면

- 제목 `기존 할 일 가져오기`
- 검색 `할 일 또는 일정 이름 검색`
- 탭 `일정 없는 할 일` / `다른 일정의 할 일`
- 옵션 `완료된 항목 포함`, 기본 꺼짐. 기본 목록에는 진행 중·보류도 포함한다.
- 기본 탭은 일정 없는 할 일. 체크박스로 여러 항목 선택.
- 각 행에 제목, 우선순위, 마감, 상태. 다른 일정 탭에는 원래 일정 이름도 표시한다.
- 검색·탭 변경 시 선택은 유지. 하단 선택 요약에 숨겨진 선택도 포함하고 `선택 초기화`를 제공한다.
- 이미 이 일정에 연결됐거나 편집 목록에 담긴 항목은 `추가됨`으로 선택 불가. 연결 해제 예정인 현재 일정 항목도 중복 선택하지 못하며 편집 목록에서 되돌린다.
- 검색 결과 없음: `일치하는 할 일이 없습니다.` + `검색 초기화`.
- 첫 목록 자체가 비어 있음: `연결할 할 일이 없습니다.` 완료 항목 포함 옵션은 유지한다.

### 다른 일정 탭의 이동·복사

두 개의 라디오 카드로 표시한다.

- **옮기기:** `원래 일정에서 제외하고 이 일정에 연결합니다.` 기본 선택.
- **복사하기:** `원본은 유지하고 미완료 할 일을 새로 만듭니다.`

모달에서 선택한 다른 일정 항목에는 하나의 방식을 적용한다. 방식을 바꾸면 선택된 다른 일정 항목 전체에 적용하고 하단 요약도 즉시 바꾼다. 이동과 복사를 섞으려면 한 번 담은 후 선택창을 다시 연다. 독립 할 일에는 항상 연결을 적용한다.

하단은 `연결 2 · 이동 1` 같은 요약과 `3개 목록에 담기` 버튼. `담기`는 서버 저장이 아니라 편집 목록 반영임을 문구로 설명한다. 선택 0개면 버튼 비활성. 취소·Escape는 이번 선택만 버리고 기존 편집 목록은 유지한다.

복사는 제목·설명·우선순위·분류·위치·마감을 가져온다. task_id, 생성/수정/완료 시각은 새로 생성하거나 초기화하고 완료 상태는 todo로 시작한다. 메모·AI 출처 등의 관계 식별자는 이번 범위에서 복제하지 않는다. 원본의 상세 필드 수정은 원본에 영향을 주지 않는다.

## 4. 전체 동작 표

| 사용자 동작 | 저장 전 | 저장 성공 후 | 취소 시 |
| --- | --- | --- | --- |
| 새 할 일 추가 | 초안 한 줄 추가 | 새 ID로 생성, 일정 연결 | 생성 안 함 |
| 독립 할 일 연결 | 연결 예정 | 같은 ID에 일정 연결 | 독립 상태 유지 |
| 다른 일정에서 이동 | 원래 일정명과 이동 예정 표시 | 같은 ID의 연결 일정 변경 | 원래 일정 유지 |
| 다른 일정에서 복사 | 복사 예정, 미완료 초안 | 새 ID 생성, 원본 유지 | 복사본 생성 안 함 |
| 저장 대기 항목 제외 | 초안에서 제거 | 해당 작업 없음 | 원본 영향 없음 |
| 기존 항목 연결 해제 | 연결 해제 예정, 되돌리기 가능 | 할 일 유지, schedule_id 없음 | 원래 연결 유지 |
| 기존 항목 제목·마감·완료 수정 | 수정 예정 | 같은 할 일에 반영 | 원래 값 유지 |
| 선택창 취소 | 이번 선택만 버림 | 해당 없음 | 일정 편집 내용 유지 |
| 편집 화면 취소·닫기·Escape | 변경이 있으면 이탈 확인 | 해당 없음 | 변경 버리기 선택 시 원복 |

변경이 없는 편집 화면은 확인 없이 닫는다. 변경이 있으면 `작성 중인 변경사항을 버릴까요?` / `계속 작성` / `변경 버리기`. 저장 성공 후에는 확인 없이 닫는다. 편집 화면에는 할 일 자체의 삭제 기능을 넣지 않는다.

## 5. 상태·오류 처리

| 상태 | 화면 동작 |
| --- | --- |
| 목록 조회 중 | 결과 영역에 스켈레톤, 검색과 닫기는 사용 가능 |
| 조회 실패 | `할 일을 불러오지 못했습니다.` + 재시도. 이미 담은 초안 유지 |
| 저장 중 | `저장 중…`, 중복 제출과 편집/닫기 잠시 차단, 진행 상태 알림 |
| 저장 실패 | 초안 유지, 상단 또는 하단 오류 + 다시 저장. 저장 성공으로 표시하지 않음 |
| 선택 후 원본이 삭제·이동·수정됨 | 해당 항목에 `원본이 변경되었습니다.` 표시. 최신 내용 확인 또는 목록 제외 후 재저장. 다른 변경도 아직 반영하지 않음 |
| 선택 권한 없음 | 변경 가능한 개인 할 일만 조회하고 서버에서도 권한 검증 |
| 회사 일정 | 기존 정책상 개인 할 일 연결이 불가하므로 편집 버튼 제공 안 함. 필요한 위치에 짧은 정책 안내 |
| 반복·여러 날짜 일정 | 여러 일정에 한 할 일을 동시에 연결하지 않음. 이 기능의 최초 적용은 단일 개인 일정. 일괄 생성에서는 가져오기 비활성 + `할 일은 일정 생성 후 각 일정에서 연결할 수 있습니다.` 안내 |

시안의 가상 저장은 성공 흐름을 보여준다. 서버 오류, 권한, 충돌, 반복 일정 정책은 명세이며 시안에서 네트워크로 재현하지 않는다.

## 6. 스타일·접근성

- 기존 Flowra 토큰 사용: 배경 #f8fafc, 카드 #fff, 글자 #0f172a, 보조 글자 #64748b, 테두리 #e2e8f0, 주요 버튼 #7c3aed.
- 카드 모서리 8px, 간격 8–12px, 섹션 패딩 16px. 제목 16px, 본문 14px, 메타 12px.
- 주요 버튼·선택 행·아이콘 버튼 클릭 영역 최소 44px. 포커스 링을 제공한다.
- 완료 체크와 선택 체크는 각 화면의 역할에 맞는 접근 가능한 이름을 제공한다.
- 라디오/탭/체크박스는 키보드로 조작 가능. 모달 포커스 제한, Escape 닫기, 호출 위치 포커스 복원.
- 모바일에서는 입력과 버튼 줄바꿈, 원래 일정명 줄바꿈. 360px에서도 가로 스크롤 없음. 하단 safe-area 여백 반영.
- 다크 테마는 실제 공통 토큰 사용. 독립 HTML 시안은 라이트 모드만 제공한다.

## 7. 구현 구조 제안

현재 확인한 `Task.schedule_id`는 단일 연결 구조이며, 조회에 `schedule_filter: linked | unlinked`와 `q`를 지원한다. 생성/수정 API는 개별 요청이다. **일정+할 일의 원자적 저장 API 지원 여부는 별도 확인·구현이 필요하다.** 순차 API 호출만으로 전체 성공/전체 취소를 보장할 수 없다.

- 공통 편집기: 새 일정/기존 일정이 공유하는 할 일 초안 목록.
- 작업 모델: create / link / move / copy / update / unlink. 원본 ID, 기대 원래 일정 ID, 원본 버전(또는 updated_at), 변경 필드, 클라이언트 작업 ID를 보관.
- 원자적 저장: 일정과 작업 목록을 한 요청에 전송하고 서버 트랜잭션으로 모두 반영. ID 매핑을 반환해 신규·복사 초안을 실제 항목으로 교체.
- 중복 방지: 요청 식별자로 재시도를 멱등 처리. 응답 유실 후 재시도해도 중복 생성하지 않음.
- 동시 편집: 서버에서 원본 버전/연결 관계를 확인하고 불일치 시 전체 작업 중단.
- 저장 후 현재 일정, 이동 전 일정, 독립 할 일 목록, 전체 할 일 목록과 관련 집계를 갱신.
- 기존 `ScheduleLinkedTasks` 내부 form을 상위 일정 form에 중첩하지 않는다. 빠른 추가는 일반 입력·type=button·명시적 Enter 처리로 구성.

## 8. 검수 시나리오

1. 한글 제목 3개를 Enter로 연속 추가할 때 조합 중 중복 추가/일정 조기 저장이 없다.
2. 독립 2개와 다른 일정 1개를 담으면 종류별 요약이 정확하며, 탭·검색 변경에도 선택이 유지된다.
3. 이동 저장 시 원래 일정에서만 빠지고 ID·상태·마감은 유지된다.
4. 완료 항목 복사 시 원본은 완료 그대로이고 복사본은 새 ID·미완료 상태다.
5. 저장 전 닫기→계속 작성은 초안을 유지하고, 변경 버리기는 원본에 영향을 주지 않는다.
6. 기존 연결 해제→되돌리기 시 원래 표시로 복원된다.
7. 저장 실패·응답 유실 후 재시도에도 일부 저장/중복 생성이 없다.
8. 원본 이동·삭제·수정 충돌은 해당 항목을 특정하고 다른 변경도 저장하지 않는다.
9. 360px 화면과 키보드만으로 검색·선택·상세 설정·저장을 완료할 수 있다.
10. 마감 없음과 원래 마감 유지, 일정 종료에 맞춤, 작성 중인 빠른 입력의 저장 포함이 각각 정확하다.
