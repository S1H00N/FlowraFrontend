# 핵심 사용 흐름 QA

검증일: 2026-10-06, 2026-10-07 (Asia/Seoul)

## 실제 서비스 확인

저장된 테스트 계정으로 배포 웹의 로그인 화면과 실제 로그인 API를 호출했다. 외부 연결은 성공했지만 10월 6일과 7일 모두 로그인 API가 HTTP 401을 반환했다. 원문 오류, 계정 정보, 토큰, 화면 캡처는 저장하지 않았다. 로그인 이후 조회 및 생성·수정·삭제 검증은 아직 수행하지 못했으며 실제 사용자 데이터는 변경하지 않았다.

`artifacts/flowra-web/.env.qa.local`의 `QA_EMAIL`, `QA_PASSWORD`를 로그인 가능한 테스트 전용 계정으로 갱신해야 이어서 검증할 수 있다. 설정 파일은 Git에서 제외한다. 로컬 수정본의 실제 연동을 검증하려면 `QA_WEB_BASE_URL`도 해당 수정본을 실행하는 웹 주소로 지정한다.

## 확인한 문제와 수정

- 계정을 전환해도 React Query의 이전 사용자 캐시가 유지됐다. 로그아웃 후 다른 계정으로 로그인한 화면에 이전 계정 메모가 남는 현상을 모의 브라우저 테스트로 확인했다. 이제 로그인 세션마다 별도 QueryClient와 화면 상태를 사용하며 동일 사용자 토큰 갱신은 기존 상태를 유지한다.
- 이전 계정의 로그아웃 응답이 늦게 도착하면 다른 탭에서 로그인한 새 계정의 세션을 지웠다. 로그아웃 시작 시 사용자와 인증 정보를 캡처하고 비동기 처리 후에도 같은 로그인 세션인지 확인한다. 같은 사용자의 토큰 갱신 중에는 로그아웃을 계속 완료한다.
- 이전 사용자의 성공 응답을 처리한 뒤 새 계정의 토큰으로 연결 할 일 API를 호출할 수 있었다. 지연된 일정 저장 응답으로 재현한 뒤 공개 인증을 제외한 이전 사용자 요청의 성공·오류 응답을 취소하도록 수정했다. 취소된 날짜 동기화는 새 사용자에게 부분 실패 알림을 표시하지 않는다.
- 서버가 일정 날짜를 저장한 뒤 응답이 유실되면 화면이 이전 날짜를 계속 보여줬다. 저장 실패 후 일정·할 일·홈을 다시 조회하며 쓰기 요청을 자동 재전송하지 않는다.
- 연결 할 일 날짜를 갱신하기 전에 홈을 조회하면 이전 마감일이 남을 수 있었다. 날짜 동기화가 완료되거나 일부 실패한 뒤 할 일·홈의 서버 상태를 다시 조회한다.
- 세션 초기화가 이메일 인증 완료 화면까지 다시 만들면서 일회용 인증 요청을 반복할 수 있었다. 공개 인증 화면을 유지하고 보호 화면·회사 초대·푸시 연결만 세션 경계에서 초기화하도록 보완했다. 계정 변경 시 QueryClient는 새로 교체하며 이전 클라이언트는 화면 반영 시점에 정리한다.

일정 저장 응답이 유실된 경우 연결 할 일 동기화를 추측해서 수행하지 않는다. 서버의 저장 상태를 다시 읽고 실패를 표시하며 사용자가 저장 결과를 확인할 수 있게 한다. 시간·완료 상태 보존, 마감 없는 할 일 제외, 여러 날 일정의 마감일 자동 변경 제외 정책을 유지한다.

최초 브라우저 실행의 날짜 관련 실패 4개는 새로고침 후 기본 주 보기를 월 보기로 전환하지 않은 가정과, 월 일정이 날짜 셀의 자식이라는 가정에서 발생했다. 실제 일정 편집 화면을 다시 열어 저장 날짜를 확인하도록 테스트를 보완했다. 이후 활성화한 Google 모의 검사에서 이메일 인증 화면의 세션 초기화 회귀를 확인하고 제품 코드와 단일 전송 회귀 검사를 함께 보완했다.

최종 브라우저 실행은 동시 편집 중인 파일의 중간 저장 상태가 섞이지 않도록 `artifacts/flowra-web/tmp/core-qa-20261007-1`에 고정한 현재 소스 사본을 빌드했다. 소스 161개의 구문 검사와 사본 타입 검사를 통과했고, 이번에 수정한 제품 소스 7개가 원본과 동일함을 확인했다. 다른 창에서 작업 중인 홈 화면 파일은 수정하지 않았다.

원본 실행 결과는 `artifacts/flowra-web/playwright-report-core-lifecycle-verified/`에 있으며, 여러 실행을 합친 [QA 보고서](report.html)와 `run-summary.json`은 로컬 생성물로 Git에서 제외한다.

## 실제 저장 검사

조회 전용 검사는 `test:e2e:live`, 저장 흐름 검사는 별도 `test:e2e:live:write`로 실행한다. 저장 검사는 UUID가 포함된 QA 일정·연결 할 일·메모만 생성하고, 생성 ID와 저장된 QA 이름을 확인한 데이터만 수정·삭제한다. 종료 시 남은 이번 실행 데이터를 정리하고 남은 데이터 수와 정리 불확실 여부를 기록한다. 기존 사용자 데이터, AI 분석, 메일, 푸시, 회사 및 공유 기능은 이 검사에서 수정하지 않는다.

```powershell
pnpm.cmd --filter @workspace/flowra-web run test:e2e:live
$env:QA_MUTATIONS='1'
pnpm.cmd --filter @workspace/flowra-web run test:e2e:live:write
Remove-Item Env:QA_MUTATIONS
```

저장 검사는 UI로 로그인하고 일정·연결 할 일·메모를 생성·수정한다. 일정 날짜 이동 후 연결 할 일의 시각 보존, 완료 처리, 새로고침과 새 로그인 후 영속성, UI 삭제 후 서버에서 사라진 상태까지 확인한다. 저장 코드 자체는 로컬 HTTP 모의 환경에서 위 흐름과 실패 시 정리를 확인했다. 실제 서비스의 저장 성공을 확인한 결과는 아니며, 실제 로그인 문제를 해결한 뒤 결과를 추가해야 한다.

이후 실제 환경 확인에는 두 계정 간 데이터 격리와 공유 권한, 반복 일정 일부·이후·전체 수정, 실제 Google 로그인·메일·푸시·AI 결과를 포함한다.
